3Pharos's spot

How Pharos does it

  1. You ask a question, in Pharos or to your agent
  2. An AI agent reads the project through MCP
  3. It writes a recipe using Pharos's building blocks
  4. Pharos checks the recipe and draws the view
  5. The blocks read live project data
  6. The view is saved: you and agents can change it, and every change is kept in history

What's particular about this spot (none of it is unique)

  • Blocks made for projects (stages, tasks, decisions), plus general blocks for any record.
  • Views read live data, so numbers stay current without asking the AI again. Written text on a view doesn't update.
  • Views are saved with a history of every change, and both you and agents can edit them.
  • Other tools can save their views too; this combination fits a project workspace, but it isn't exclusive to Pharos.

What Pharos rules out, and why

Ruled out

AI-written view code. The AI may only arrange tested blocks, so a view can't run code nobody reviewed.

Ruled out

Swapping its blocks for A2UI's basic set. Pharos would lose its blocks made for projects.
