The explicit database path is required. The loader never uses a default destination, refuses `.pharos` path components, and refuses an existing database or SQLite sidecar. Exclusive file creation prevents two loaders from appending to the same target. A failed apply closes and removes only the newly created database/sidecars. Reruns exit nonzero with a refusal; use another fresh path for each evaluation. Existing files are never reset or merged. No package scripts or product files were changed.

Progress and completion/failure messages go to stderr. Stdout contains one JSON object with version, today, SHA-256 checksum, entity counts, and the mapping from fixture refs to generated IDs. Keep that mapping with run evidence to identify expected tasks independently of generated UI layout.

The checksum hashes canonical JSON containing version, today, and every resulting entity's type/data/normalized identity. Object keys and entity records are sorted; arrays retain order. Generated IDs, including nested occurrences, map back to fixture refs; automatic Overview IDs map to their project's `/default-overview` alias. Entity creation/update timestamps and revision metadata are excluded, while semantic dates, expiry timestamps, options, defaults, and view specs remain included. Store revision timestamps are also fixed to noon UTC on the evaluation date. A changed task title demonstrably changes the checksum. Changes to schema defaults or automatic views can change it even with unchanged fixture input, making those baseline changes visible.

Dates remain fixed rather than shifting to the loading day. Overdue means an open task due before 2026-10-07; done/cancelled tasks are excluded. Due this week means open tasks due in the inclusive UTC calendar week 2026-10-05–2026-10-11, including already overdue tasks in that week. Fixture `expected` lists define the exact stable refs: Catalog has 2 overdue, 5 due-week, 1 explicitly blocked, and 2 dependency-obstructed tasks; Workshop has 2, 3, 1, and 2 respectively. These categories may overlap. A dependency obstruction means an open task with a prerequisite whose meaning is not done.

Future runners must pass `today: fixture.today` to `runQuery`, as the test does, and freeze application/browser clocks to this date when exercising expiry or other wall-clock behavior. Loading a fixture does not override a running application's clock. Stored risk widgets use fixed cutoff dates. The nonexpired answers are keepable on the evaluation date; their expiry does not advance on later loads.
