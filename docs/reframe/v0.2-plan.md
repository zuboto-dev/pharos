# Pharos v0.2 plan

2026-10-13 · agreed with the owner

v0.2 runs as two parallel tracks with one builder each, plus the plumbing they need. **There is one review
at the end:** builders work through the plan, then the owner gets a single work report and reviews
everything at once. In between, the owner gets no checks and no restarts. Independent model checks are
batched too, into one safety review at the end. Every feature still ships with a sample view, built on
an isolated server and shown in the report.

## Track A · Feature UI (what Pharos can show and do)

| #   | Work                                                                                                                                                                      | Stage        |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------ |
| A1  | Records and packs: projects keep their own kinds of records; Car and Money packs                                                                                          | R8           |
| A2  | Query checks: pages are checked against record fields; totals and due dates are fact-checked                                                                              | R8           |
| A3  | Decision block: options side by side with pros, cons and sources; pick one on the page                                                                                    | R10.19       |
| A4  | More packs: Music, Study, Company documents (expiring soon)                                                                                                               | R9           |
| A5  | Act in place: "Log a service" / "Mark paid", a short form, every page updates, Undo                                                                                       | R10          |
| A6  | Ask about one block: the agent changes only that block                                                                                                                    | R10          |
| A7  | Changed since you looked; stale answers marked; agent editing/working data                                                                                                | R11          |
| A8  | Gallery and file follow-ups: set a picture, alt text and tags in the drawer; a picture clears when its file is deleted; expiry reminders; Settings wording for file names | R7 follow-up |

## Track B · Visual and motion UI (how it looks and moves)

| #   | Work                                                                                                                                                                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| B6  | One visual system: tokens for colour, type, spacing and radius across blocks; every block checked in dark mode                                                                                  |

## Under the hood

- C1: a smaller apply tool schema (it is near its cap after R7.12–R7.13)
- C2: agent compatibility: five scenarios (`eval/compat`) that Claude Code and Codex run against an isolated server, so the README can say which agents work (OpenCode later; replaces the GPT pack-guide comparison)
- C3: measure and release (R12), after the owner's review

Then: one independent safety review (GPT) of everything, one fix round, and the work report with links
to every sample view. The owner restarts once and reviews everything at once.

Rules unchanged: at most two code agents at once; isolated servers and database copies; never the
live instance; made-up or public data only.
