Save the following as `$SCRATCH/mcp-walkthrough.mjs` and run `rtk node ../mcp-walkthrough.mjs` from the clone. Imports resolve to the SDK installed in the fresh clone (no separate client dependency install). The helper was based on the [official SDK v1 client documentation](https://github.com/modelcontextprotocol/typescript-sdk/blob/v1.x/docs/client.md), fetched through Context7, and the clone's advertised tools/schema.

```js
import { Client } from './clean/apps/server/node_modules/@modelcontextprotocol/sdk/dist/esm/client/index.js';
import { StreamableHTTPClientTransport } from './clean/apps/server/node_modules/@modelcontextprotocol/sdk/dist/esm/client/streamableHttp.js';
import assert from 'node:assert/strict';
const client = new Client({ name: 'W2.1 clean-checkout verification', version: '1.0.0' });
async function call(name, args) {
  const result = await client.callTool({ name, arguments: args });
  console.log(JSON.stringify({ tool: name, arguments: args, result }));
  assert.ok(!result.isError, `${name} returned an error`);
  return JSON.parse(result.content.find((c) => c.type === 'text').text);
}
try {
  console.log('[1/5] Connecting to documented HTTP endpoint on port 4311');
  await client.connect(new StreamableHTTPClientTransport(new URL('http://localhost:4311/mcp')));
  console.log(JSON.stringify({ server: client.getServerVersion() }));
  console.log('[2/5] Discovering tools and checking for projects');
  console.log(JSON.stringify({ tools: (await client.listTools()).tools.map((t) => t.name) }));
  const before = await call('list', { type: 'project' });
  assert.equal(before.length, 0);
  console.log('[3/5] Creating the single authorized scratch project');
  await call('apply', {
    message: 'Verify clean-checkout README MCP connection using an isolated scratch project.',
    operations: [
      {
        op: 'create',
        type: 'project',
        data: { name: 'W2.1 clean checkout', summary: 'Synthetic README verification fixture' },
      },
    ],
  });
  const projects = await call('list', { type: 'project' });
  assert.equal(projects.length, 1);
  console.log('[4/5] Reading project snapshot');
  const snapshot = await call('project_snapshot', { projectId: projects[0].id });
  assert.equal(snapshot.project.id, projects[0].id);
  assert.equal(snapshot.project.name, 'W2.1 clean checkout');
  console.log('[5/5] Snapshot assertions passed');
} finally {
  await client.close();
  console.log('MCP client closed');
}
```

## Findings and reproduction steps

- **F1 — pnpm absent; documented fallback works (environment, recovered).** On this PATH, run `rtk pnpm --version` (127), then any README pnpm setup command (RTK returns 1). Replace pnpm with the README's `npx pnpm@12.9.1`; with a writable npm cache, it reports 12.9.1 and all checks pass. This replacement is documented, not a README defect, but is recorded as a literal-command deviation.
- **F2 — default npm cache is unwritable (environment, recovered).** Run `rtk npx pnpm@12.9.1 --version` or `install --frozen-lockfile` in the fresh clone under this sandbox: exit 1, `EPERM` opening the default cache. npm suggests root-owned cache files, but ownership was not independently verified. Retry with `npm_config_cache="$SCRATCH/npm-cache"`: both exit 0. This extra environment variable is not in the README. The install also automatically falls back to a temporary pnpm store after a hard-link warning.
- **F3 — literal dev/service setup remains unverified (task constraint).** Follow the Setup block: its second command is `pnpm dev`; the macOS service branch asks for `pnpm service install`. Both are explicitly prohibited by this work item's ground rules. To reproduce this isolated verification, skip those commands and use the README's alternative build/start path on port 4311 with scratch database/log paths and answering disabled. This also changes the order by building before MCP connection. A literal dev/launchd walkthrough cannot be claimed from this evidence.
- **F4 — connection/client adaptation (task-authorized).** Replace only the port in the README URL with 4311 and run the SDK helper above, instead of registering a persistent agent client. Start with an empty scratch database; `list` returns no projects, so execute the single message-bearing `apply`, then `project_snapshot`. MCP protocol behavior passes; persistent client configuration and stdio are outside this run. No additional authorization or personal configuration was needed.
- **F5 — remote/main revision mismatch (coverage limitation).** Compare `git rev-parse HEAD` in the fresh network clone with `git rev-parse --short HEAD` in main: remote is `8bb6b32`, main is `c28ca51`. The requested network checkout succeeded, so no local clone was substituted. This evidence establishes the public revision's behavior only.
- **F6 — RTK wrapper changes command presentation (required harness adaptation).** Prefix README commands with `rtk` as instructed. With pnpm absent, `rtk pnpm typecheck` reports “TypeScript: No errors found” but exits 1. Reproduce with that command on the same PATH; use exit status and the successful npx retry, not the misleading text. This is a harness observation, not a Pharos typecheck defect.

No reproducible Pharos setup or MCP product failure remained after these adaptations. Build size warnings are recorded above but did not require a command deviation. Optional formatting writes, alternate client branches, and service administration were not treated as mandatory sequential setup operations.
