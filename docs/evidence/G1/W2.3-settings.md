## Findings

All are minor. None block the release gate. W2.5 can decide whether to act on them.

1. Page behavior not confirmed in a browser. Theme persistence and the live-updating pause switch rest on code reading and the happy-dom tests. Reproduce: open `/settings`, choose Dark, reload, and confirm the dark theme is kept without a flash. Also pause in one tab and confirm a second tab updates (it relies on the SSE `agent` event).
2. In the `off` and "not set up" states the switch is shown off and disabled, so a viewer cannot tell it is disabled by configuration except from the status line. The status line does explain it, so this is cosmetic. Reproduce: start with `PHAROS_AGENT_COMMAND=off` and open `/settings`.
3. Pause state is stored in the database (`settings` table), not the environment, so a paused server stays paused after restart, and this is not stated in README or the Settings page. Behavior is sensible, but the docs only say "pause answering in Settings". Reproduce: pause, restart the server on the same database, and `GET /api/agent` still shows `enabled:false`.
4. `GET /api/settings` shows `enabled:true` while `mode:"off"`. The flag only reflects the stored pause value and is meaningless when answering is off. The page handles it by checking `configured`, so there is no visible effect. API consumers could misread it.
5. The Settings "Server" row says "change it with PORT", but when run via the launchd service the port comes from the service definition, not the shell. Not tested here (the service was out of scope).
