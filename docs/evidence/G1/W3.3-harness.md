## Running

From the repository root with dependencies installed:

```sh
rtk npx pnpm@12.9.1 --filter @pharos/server exec node --import tsx --conditions=development ../../eval/harness/run.ts --dry-run
rtk npx pnpm@12.9.1 --filter @pharos/server exec node --import tsx --conditions=development ../../eval/harness/run.ts --mock success
```

Options: `--case <path>`, `--output <directory>`, `--scratch <directory>`, `--timeout-ms <milliseconds>`, and exactly one of `--dry-run`, `--mock <scenario>`, or `--agent-command <command>`. Paths supplied on the command line resolve from the command's working directory (the server directory in the examples); the built-in sample and default output resolve from the repository root. No root package script was added.

Mock scenarios are `success`, `wrong_facts`, `query_error`, `agent_refusal`, and `timeout`. The mock is deterministic REST traffic, with synthetic usage records; it never calls a model. `--agent-command` is explicit opt-in for a future configured agent and was not exercised. It must emit the structured adapter records described below to yield usage metrics. Ordinary prose logs produce unavailable metrics, not fabricated zeros.

Default output is `eval/results/<run UUID>/`, now gitignored. Each run has its own fresh scratch database, agent log and process group. Port selection excludes 4300. A race for the released ephemeral port fails readiness rather than accessing another server; the harness never requests the live port. Cleanup terminates the server/agent process group and removes its temporary database. SIGINT/SIGTERM also terminate the group.

The fixture contains an open request control. Setup dismisses open requests before starting the server, records that setup revision in the starting snapshot, and submits only the evaluated request during the timed window. It does not change the fixture JSON. Fixture loading still enforces the loader's checksum and fresh-file protections.

## Evidence and measurement boundaries

The result bundle records the case/fixture, loader ID map, complete materialized starting snapshot, catalog snapshot, measurement procedure, observer REST/status events, observed candidate view/data captures, last stored view/effective Board, raw agent log, server log, end snapshot and ordered raw revision/change window. Earlier observed candidates remain in numbered files even if the agent later updates its answer. Polling can miss intermediate writes; the revision export retains their persisted changes. No painted-render observation is claimed.

`latency` uses the observer's monotonic clock beginning immediately before request dispatch, including server batching and agent settlement. Successful runs end after persisted checks; deadline values are censored at the configured limit, with actual observation elapsed time separately retained. `view_exists_ms` is a persistence milestone. `agent_process_ms` comes from captured `/api/agent.lastRun.durationMs`; it is not workflow latency. Revision timestamps are retained for provenance, never substituted for paint time.

TTUC is explicitly `null/capture_error` because no browser paint is captured. Full task completion and correction burden are unscored. The sample checks initial/final persisted risk membership, answer/request linkage and unrelated writes; it does not certify all W1.2 atomic facts, extra claims, layout, human comprehension, or B/C action/refinement/reuse workflows. The declarative script metadata describes this supported single-request flow; it is not a general script interpreter. Cases requiring browser capture or scripted corrections are rejected.

`version_set` includes commit, dirty-file hashes, Node version, lockfile hash, catalog hash, exact materialized-start checksum, stable loader checksum, procedure/case/check hashes, fixture variant, repetition, adapter identity, and model/prompt boundaries. Missing provenance is explicit null. The invocation wrapper captures the actual expanded `PHAROS_PROMPT` and request/project IDs; it does not claim visibility into provider-managed instructions. Its logged command uses environment indirection rather than an absolute checkout path.

W3.1 generates entity IDs when loading. Consequently the exact materialized-start checksum varies across fresh runs, while `loader_checksum` identifies the normalized fixture semantics. Both hashes are retained, with the full snapshot and ID map. W3.2 must freeze/replay actual materialized starting identities before claiming exact paired W3/W15 comparability. The harness does not quietly substitute the less complete loader checksum for W1.5's snapshot checksum. All sample results set `comparison_eligible: false` and `attribution_complete: false` pending the full capture protocol. Query scoring pins the fixture date; browser/server/agent wall clocks are not frozen, so date-sensitive real-agent comparisons remain out of scope.

## Structured adapter

`metrics.ts` accepts newline-delimited `PHAROS_EVAL:` JSON records, each containing `version: 1`:

- `tool_attempt`: `invocation_id`, `call_id`, `dispatch_attempt`, `tool_name`, `server` (`pharos`/`other`), `outcome` (`success`/`error`). Deduplication uses the invocation/call/attempt triple. Re-dispatched retries have another attempt key.
- `model_usage`: `request_id`, `final: true`, disjoint `input_uncached`, `cache_read_input`, `cache_write_input`, `output`, optional `reasoning_output` and `actual_cost_usd`. Final records deduplicate by request ID; session summaries must not be emitted as additional model requests. Provider adapters must preserve raw provider records in the log and map cache categories correctly. Optional `provider` and `model_id` are retained in run provenance.
- `diagnostic`: `classification` (`query_error`/`agent_refusal`), optional `message`. No refusal/error inference from arbitrary prose is attempted.
- `capture_end`: run-wide `tool_attempts_complete`, `model_usage_complete`, `billing_complete` booleans. Missing/malformed/conflicting capture produces null totals and labeled known subtotals. A structured adapter is trusted instrumentation, not adversarially verified telemetry.

The mock writes these lines to stdout; the actual `shellRunner` supplies its unchanged timestamped header and exit footer. The isolated log is one invocation, captured with byte offsets from zero through its final byte; headers in agent output are not used as slice boundaries. Agent-dispatched synthetic REST apply is modeled as one mock tool call, while observer REST calls are excluded. The mock's USD 0.001 is a parser test value, not money spent. There is no estimated/reference-rate cost without a frozen rate card. Verified answering-off runs yield zero new calls/tokens/cost.
