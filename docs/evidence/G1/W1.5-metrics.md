## Scope

This is the measurement procedure for the G1 evidence artifact, to be frozen before baseline W3 and reused for final comparison W15. It extends [W1.1](W1.1-workflow-inventory.md)'s A (Ask → answer), B (refine → retain) and C (act → reuse) workflows. It defines measurements, not improvement targets or baseline results. No benchmark, server, agent run or live-instance access was performed for this task. Supplementary captures below are requirements for the evaluation harness; they are **not existing product telemetry** and this task does not implement them.

Use an isolated synthetic fixture and one case at a time. Give each execution a `run_id`, `case_id`, fixture variant and repetition index. Restore the exact starting fixture before each repetition; preparation, login/navigation to the declared starting screen, seeding and reviewer scoring occur outside the timed window. All prescribed human actions, normal waits, agent discovery, retries, corrections, saves and reuse steps inside that window count. Do not share an automatic agent batch across cases: `AgentRunner` queues project IDs, gathers their open request IDs when starting a run, serializes runs and defaults to a 2,000 ms batch wait (`apps/server/src/agent-runner.ts:203–264`). If sharing cannot be avoided, treat the batch as one experiment; do not divide its cost/tokens/latency equally into fictitious per-case values.

Freeze the procedure revision, case text/check hashes, repetition count, human-action schedule, viewport, timeout, repair allowance, date/timezone and agent configuration before W3. Carry them into W15. Changed product commits/catalogs/prompts/models are recorded experiment variables; changed case checks, fixture semantics or measurement rules require rerunning W3 with the new protocol. Record deviations; do not silently change the denominator, stop rule or token adapter.

Treat each phrasing/variant and each separately restored failure/Undo probe as a named executable case variant with its own run record and all eight metrics. Main-path metrics never absorb a probe's calls or cost without labeling that scope. When a case's completion condition requires probes, overall case completion for a repetition is the Boolean AND of its main-path and required-probe completion values; missing required probes mean incomplete evidence, never a pass. Publish the component results, not a single blended latency. For a rejection probe, useful checks may require the expected visible error/conflict and unchanged rendered/persisted state; an unchanged starting screen alone cannot qualify. Freeze the required probe set in W3 and retain it in W15, including requirements pending future conflict work.

### 2. Required run capture and time boundaries

Each run bundle must contain a manifest plus these logical records (filenames are suggestions, not additional outputs of W1.5):

- `agent.log` raw slices and a structured agent transcript/usage export. A capture adapter must preserve the provider's original records and document its field mapping/version. Configure structured capture before W3; ordinary textual logs are insufficient for tool, token and cost measurements.
- `events`: external observer records `{run_id, event_id, kind, monotonic_ms, utc, source, payload, request_id?, view_id?, revision_id?, invocation_id?, artifact_ref}`. Include start/terminal events, input dispatch, correction instructions, REST request/result/errors, raw SSE receipt, relevant data response, candidate painted view observations, check results and process starts/exits. Use synthetic author labels (`human:owner`, named evaluation agents) and cross-check them with revision authors; a correction's actor comes from the trace, not author kind alone.
- Full fixture/start snapshot, end snapshot and raw revision/change export; candidate view/spec/data snapshots at every scoring checkpoint. Keep earlier wrong output even after repair. Check records are `{check_id, checkpoint, expected, observed, pass, evidence_ref}`; fact records additionally have `fact_id` and reference the immutable oracle.
- Normalized tool calls, per-request model usage and correction annotations as specified below. Preserve malformed calls, failures and rejected writes as well as successful revisions. Every invocation/agent continuation belongs to this run until the terminal event; evaluation observer queries are labeled separately.

Use **one external monotonic clock** for start, all browser input/render observations, process completion receipt and terminal checks. If capture crosses clock domains, timestamp receipt in this observer and retain native times for diagnosis. Never subtract a browser `performance.now()` value from a server ISO timestamp. Record observer clock origin, resolution and paint sampling method. UTC times establish provenance only; fixture date semantics are separate from elapsed-time clocks.

`t0` is immediately before dispatching the first case action on the prepared starting screen: Submit for A, the declared first refine/keep action for B, the declared first task action for C. An external-agent variant uses the timestamp immediately before delivering its first case instruction. Fix this choice in the case; do not switch between request creation, agent spawn and button dispatch across W3/W15.

For each relevant view/data change or navigation, the observer captures a candidate visible view after the next paint opportunity (two successive animation-frame callbacks; timestamp the second). Bind the capture to its DOM/screenshot, effective spec and exact dataset response. Check that immutable capture against the case's `useful_checks`. A candidate passes only if all those checks pass: correct required content, intended empty states, eligible target view, usable rendering and required data freshness. For checks spanning two windows, capture both at the required state and use the later observation timestamp; retain their individual times. Preserve every candidate, including failures. The metric is the **first observed qualifying painted render**; sampling introduces a recorded upper bound on actual first paint. Later reviewer approval must not move its timestamp. SSE arrival, a preview, answer notification, loading shell, or a pre-existing starting view cannot qualify on its own.

`t_end` is the earliest observer time at which the declared script has finished, permitted corrections/agent continuations have settled (no queued/running case work), and the final persistence/render/reopen checks have recorded their results. With success, all final checks pass. With an exhausted repair allowance, terminal failure or deadline, record that terminal event and outstanding failures. There is no untimed optional polishing. A crash is a terminal failure only when capture can determine its outcome; loss of observation is a capture error. Prescribed reuse delay and owner interaction time remain in elapsed latency; record wait durations for interpretation and use the same schedule in both phases. A case's owner comprehension exercise (A §7) is task work inside the window; later independent evidence scoring is outside it.

### 3. Metric definitions and exact extraction

| Metric | Computation and extraction rule |
| --- | --- |
| **Factual correctness, per checked fact** | Cases predeclare atomic `(checkpoint, fact_id)` assertions and expected values/sets/relations from synthetic fixture data plus prescribed mutations. Set `f_i = 1` only when the captured output at that checkpoint (rendered view, or explicitly declared spec/persisted-state fact) establishes the expected assertion correctly, otherwise `0`. A wrong, contradictory, missing, unsupported or unobservable required fact scores `0` when capture is otherwise complete. Exact ID-set equality checks include exclusions; split counts, status meanings, due-date membership, dependency edges and prose claims into separate checks rather than grading a whole screenshot by impression. Rate `F = sum(f_i) / N`, with `N` frozen before W3; publish every `f_i` and `N`. Repeating the same claim within a checkpoint does not add denominator weight; a declared reuse checkpoint is a new temporal assertion. Score the **first presented task output** at initial checkpoints, before corrections, and the declared refined/action/reuse checkpoints separately; repairs do not overwrite initial failures. Report final fact scores alongside initial ones. Inspect full text and all rows, including offscreen/paginated content, using DOM/spec/data evidence. Audit extra generated claims separately and flag any false extra claim in the completion non-contradiction check; they cannot dilute the frozen primary denominator. |
| **Task completion, binary per case** | `C = 1` iff every predeclared completion check passes by `t_end` within the deadline/repair allowance; otherwise `C = 0`. Final fact checks and absence of false extra claims are mandatory completion checks. Include persisted state, intended task effects, stable widget/layout preservation, round-trip/reuse/freshness and safety invariants required by that case. Obtain values from check records tied to browser captures, raw revisions and end/reopened dataset/spec. Answered request, process exit 0, valid Board schema or a successful save alone cannot yield `1`. Log `completed_without_correction` separately as `C == 1 && burden == 0`; completion after permitted repair is still `1`. |
| **Correction burden** | Integer `B = H + A`, where `H` is count of distinct human corrective actions/instructions and `A` count of distinct agent repair attempts under the rubric below, over `[t0, t_end]`. Publish `H`, `A`, event IDs, cause links, succeeded/failed status and exclusions. Use interaction/transcript/tool evidence to identify intent and attempts, then raw revision before/after and error/preview results to verify them. Do not count revisions, changed fields or error messages mechanically. Unresolved defects are recorded and affect correctness/completion, even if no one attempted repair (`B` can be 0 for a failed run). |
| **Time to useful content** | `TTUC_ms = min(t_render of qualifying candidates) - t0`. Qualifying checks are frozen in the case and evaluated on that candidate's immutable view/spec/data. For B require the declared refined result, for C the declared post-action result; the starting saved view does not qualify. Use observer-painted-view records, with SSE/data response/revision IDs as supporting correlation. If none qualifies, store `value_ms: null`, `status: not_reached`, and observation bound `t_end - t0`; never substitute exit time or zero. A later stale/wrong view can fail completion despite an earlier qualifying render. Missing paint capture is `capture_error`, not `not_reached`. |
| **Total latency** | `latency_ms = t_end - t0`, including batching/queueing, calls, rendering, prescribed human actions/waits and repair. Save terminal kind (`success`, `failure`, `deadline`) and completion `C`. A deadline result is a censored observation at the predeclared limit, not a successful completion latency. Runner `lastRun.durationMs` and log header provide a separately named agent-process diagnostic, never the workflow number. Missing start/end capture yields `null/capture_error`. |
| **Tool calls** | Count each agent-dispatched tool invocation attempt in `[t0, t_end]`, across all case invocations: `T = number of normalized attempt records`. Key by `(invocation_id, call_id, dispatch_attempt)`; collapse repeated streaming fragments/results for that attempt. A retry dispatched again is another attempt even with identical arguments. Count reads, writes, preview calls, Pharos `catalog_list`/`catalog_describe` calls, failed/invalid/rejected calls and non-Pharos tools; report per tool/server plus `pharos`, `other`, success/error subtotals. An atomic `apply` with ten operations is one call; a save's inline preview is not a separate tool call. MCP protocol discovery (`tools/list`) and handshakes, REST owner actions, SSE events, internal server operations and observer checks are excluded. Source is structured agent/tool transport capture (possibly emitted into `agent.log`), not number of revisions or textual mentions. If dispatches are not completely captured, `T = null/incomplete`; a partial count is only a labeled lower bound. |
| **Tokens** | Normalize each unique billable model request to disjoint categories: `I` uncached input, `R` cache-read input, `W` cache-write input, `O` output. `input_total = sum(I+R+W)`, `output_total = sum(O)`, `tokens_total = input_total + output_total` over all requests/agents/repairs in the run. Reasoning tokens, when supplied as an output subset, are reported separately and not added again. Preserve raw provider usage, units and request IDs; a documented adapter must subtract cache categories when a provider's input field already includes them. Cache write TTL/categories remain separate for cost. Prefer finalized per-request records, deduplicate repeated stream/final/cumulative reports, and do not add a session summary on top of its requests. Actual billable retries count even when model/tool output failed. Do not estimate from text length or count fixture/tool JSON again as independent tokens. Incomplete/ambiguous usage yields null totals plus a labeled known subtotal; absence of an agent phase with verified complete capture yields zero. |
| **Cost (USD)** | Primary `cost_usd = sum(actual provider-reported attributable cost per unique billable request)`, or the finalized session cost once if it covers exactly this run and per-request cost is unavailable. Include all case agents, retries and repairs; never add request and session costs together. Keep reported precision and round only display (six decimal places). If no actual monetary charge is reported, publish primary `null/unavailable` and separately `estimated_cost_usd = sum((I*p_I + R*p_R + W*p_W + O*p_O)/1,000,000 + other documented charges)` using captured usage and a dated, archived model/provider rate card in USD per million tokens. Apply documented cache TTL/tier/batch rules, not guessed prices; record source URL, effective/retrieval date and rate-card hash. Subscription access is not $0 or an inferred share of the subscription. No agent billing events means zero only with complete capture. Unknown usage/rates yields unknown estimate, not zero. For W3/W15 token-efficiency comparison, additionally reprice both runs against one frozen reference rate card; show actual, contemporaneous estimate and constant-rate estimate as distinct series. Tool/API charges outside model billing are separately reported if present. |

Fact ground truth must be independent of the code being evaluated. Specify custom option **meanings**, completed/cancelled exclusions, explicit blocked status versus unfinished dependencies, sorting/limits, intentional empty sets, and calendar-week versus rolling-seven-day boundaries. For date-sensitive cases record fixture evaluation date/timezone and pin the semantic date used by browser, preview and agent consistently (or use a declared deterministic date materialization strategy). `previewBoard` defaults to the server's local date (`preview.ts:383–390`); identical fixture bytes alone do not freeze “today.” Wall/monotonic measurement must continue advancing normally. If the harness cannot reproduce the semantic date, date-sensitive paired results are invalid.

### 4. Correction burden rubric and independent agreement

Annotate every candidate intervention with `{event_id, actor, class, defect_id, caused_by?, target_ids, evidence_refs, result}`. `class` is `human_correction`, `agent_repair`, `planned_step`, `initial_construction`, `observation`, or `infrastructure_retry`. A defect is a violation of a frozen case requirement, schema/query/render contract, or preservation/freshness invariant, evidenced before the attempted correction. Changes in preference that were not case requirements are protocol deviations, not retrospectively invented defects.

| Decision | Count rule and examples |
| --- | --- |
| Human correction `H += 1` | One submitted corrective instruction (even if it names multiple defects), or one direct corrective UI gesture/save. “The overdue set omits task X; include it” is one. Typing a field then saving is one, not one per keystroke. A drag/resize that auto-saves is one gesture even if it produces multiple revisions. Two separately submitted instructions or two distinct corrective saves are two. A failed/rejected/no-op corrective submission still counts as an attempted correction. |
| Agent repair `A += 1` | One dispatched remedial tool attempt following identified failure/wrong output/lost edit, or one emitted corrected response when the repair is purely textual. For an initial planned rejected save followed by a changed remedial save, the initial call contributes no burden and the remedial save contributes `A=1`; if the rejected save was itself corrective, both attempts count. Wrong saved query → corrective `view_update` is one. Repeated failed corrective writes each count. A batch fixing three widgets is one attempt; three remedial calls are three. A draft `view_preview` discovering a defect followed by a remedial revised preview/save counts as repair even before the owner sees it. A revised draft preview and corrective save dispatched separately count as two attempts; merely checking the already repaired saved view is observation. Silent internal thought/revisions without observable attempted output are not counted. |
| Human instruction plus agent execution | Count both: one correction request and one remedial agent write gives `H=1, A=1, B=2`. The two terms measure interventions/attempts, not unique defects. Link them through `caused_by` rather than merging them. A direct human corrective edit also appearing as a revision is still only one human action. |
| Planned work / initial construction | Exclude first-generation calls, ordinary discovery/preview, scripted keep/layout/scope edits, intended task completion, prescribed Undo/history revert and planned second refinement requests when their preceding state already meets the case checks. Those are workflow work, not correction. An unplanned Undo to restore an accidentally changed task or erased owner layout is a correction. A scripted agent refinement is initially normal work; repairing its lost owner edits is an agent repair. |
| Read/diagnostic/infrastructure work | Read-only snapshot/catalog/history calls and “check again” without changed output are observations. An identical transport retry after an independently captured outage is an infrastructure retry, excluded from burden but included in calls/tokens/cost/latency. A retry fixing rejected arguments or invalid component/query fields is repair. Unsupported classification is marked disputed; do not infer intent from revision messages alone. |

An intentionally invalid submission or injected outage in a frozen failure probe is a planned test stimulus. Expected refusal/recovery that meets that probe's checks is planned work, not a defect or correction. Count an additional intervention only when it attempts to fix behavior that violated those checks. This keeps failure-probe burden comparable to ordinary workflow burden.

Before W3, two reviewers independently score a small calibration trace containing planned refinement, planned Undo, wrong query repair, rejected correction and human-request-plus-agent-write. Then both independently score **every** W3/W15 run from the same frozen candidate event list and evidence, without viewing each other's annotations or aggregate phase results. The candidate list is the union of submitted human actions/instructions, agent tool attempts and emitted amended responses; exclusions are explicitly classified, so an omitted event cannot silently disappear.

Agreement check: report per-event exact class agreement `agreements / candidate_events`, per-run exact agreement on `(H,A)`, and maximum absolute disagreement in `B`. If there are zero candidates, report event agreement as N/A and independently verified `(0,0)` counts, not an invented percentage. Accept scoring only if **at least 90% event class agreement and 100% exact per-run `(H,A)` agreement** hold. Publish both original annotations. Reconcile every disputed event with evidence and record the reason; if the threshold fails, clarify the rubric and have both independently rescore all runs in **both** phases, preserving previous scores and the procedure revision. Final published counts require complete agreement after reconciliation. If disagreement remains, correction-burden results are unresolved and cannot support an improvement claim. A low burden never compensates for failed factual/completion checks.

These are manifest fields, not fields currently guaranteed by `agent.log` or revisions. Use SHA-256, lowercase hexadecimal, explicit `sha256:` prefix for hashes. Hash UTF-8 bytes; canonical JSON here means recursively sorted object keys, compact JSON, no terminal newline, arrays preserved in their declared order. Keep the hashed input alongside the digest. Use repository-relative artifact names and synthetic labels in committed evidence; exclude personal paths and secrets.

| Required field | Exact capture rule |
| --- | --- |
| `model_id` | Actual resolved provider/model ID for **each** invocation/model request, including routing/fallback/repair agents, plus configured ID. Capture from finalized provider/agent metadata; an alias such as “default” or a log command without resolution is insufficient. Record provider, agent CLI/version, reasoning/sampling settings and enabled tools. A model-free phase has an explicit empty invocation list; the overall case records any model that generated its starting view. |
| `prompt_hash` | Hash canonical JSON of the exact ordered model-facing system/developer/user instructions and task/context inputs supplied by the evaluation setup, including expanded `PHAROS_PROMPT`, MCP instructions, case prompts and correction/follow-up instructions. Record role and exact content, with an invocation/turn hash per continuation; keep initial hash and append subsequent hashes. Also retain the raw transcript for dynamic tool messages. Stable comparison uses the same initial case instruction; changed generated briefing bytes are recorded, not normalized away. The log header's literal `$PHAROS_PROMPT` is not the prompt. |

Record `sha256` of canonical JSON containing the actual `catalog_list` result, `catalog_describe` results for **all** names sorted by name, and effective template Boards used by the fixture. | `git_commit` | Full `git rev-parse HEAD` of the running server/schema/web checkout and agent integration if separately versioned; record dirty status and changed-file content hashes if dirty. | `fixture_checksum` | SHA-256 of canonical JSON of the **materialized starting fixture**: evaluation date/timezone and every synthetic entity's `id`, `type`, `data`, `createdAt`, `updatedAt`, `createdRev`, `updatedRev`, relevant starting revision/change rows, settings, and any agent cursor state, sorted by stable IDs/row keys. Include starting saved specs/requests and custom option mappings. Keep this logical export and any ID materialization map; random IDs/timestamps must be fixed before freezing W3. Never guess missing version fields. A missing required version set invalidates attribution/comparability even if some metric values can still be computed.

### 6. Fields every W1.2–W1.4 case must supply

Before W3, each case must pass this completeness check; a missing field is a case-definition gap, not a product failure:

1. **Identity/input:** case ID/version, W1.1 workflow mapping, fixture variant/export/checksum, stable project/entity/view/widget IDs or declared ID map, semantic date/timezone, custom options, exact starting screen/state and seed-view provenance. Specify whether/how automatic or external agents participate, including B/C phases that use no agent.
2. **Script:** exact prompts and contextual request fields (`viewId`, `widgetId`, `aboutId` as applicable), ordered owner/agent steps with actor and `planned` purpose, normal waits/reuse delay, persistence/reload/reopen boundaries, Undo path, viewport and navigation/open-answer policy. A deterministic observer opens an eligible answer on its declared signal; don't compare owner reaction delays with instant automatic opening.
3. **Oracle/facts:** nonempty fixed atomic `fact_checks` at named initial/final/action/reuse checkpoints, expected values/ID sets/exclusions and independent derivation; extra-claim audit rule; intended empty results; date/filter/status/dependency semantics. B checks retained spec/settings/order/IDs as factual assertions; C checks actual task state and bound-view membership, so neither requires a new question to have facts.
4. **Useful render:** eligible target view(s), milestone after `t0`, exact `useful_checks` and expected dataset revision/state. Declare an existing view's qualifying changed state for B/C. Specify render/freshness evidence even when SSE never arrives (REST-triggered reload or reopening can render; missing expected SSE remains its own failed check).
5. **Completion/stop:** binary completion predicates including final factual/non-contradiction checks, preserved owner edits/data, persistence and reuse; required focus/Undo/live-update predicates if relevant; deadline, permitted correction policy/attempt cap and terminal failure behavior. Unsupported current behavior remains an explicit failure, not a dropped check.
6. **Capture/review:** run/version manifest, clock/candidate-render method, tool/usage/cost adapter and raw evidence locations, actor/defect/correction trace, complete revision window, check/result ledger and two reviewer annotation slots. A no-agent phase produces verified zero new calls/tokens/cost, not missing telemetry; previous seed generation stays outside this run and is documented separately. Publish generation and refinement/action subphase costs if useful, without changing whole-case boundaries.
