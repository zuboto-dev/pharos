# W2.7 - Browser pass of the Settings page

Date: 2026-10-07
Written by Sonnet 5.5
Commit: d000836

Method: isolated stack on server port 4392 (Vite on 5173) with a scratch database and agent log, once with `PHAROS_AGENT_COMMAND=true` and once with `off`, following the alternate-port recipe in README Troubleshooting. A real Chrome was driven over CDP (browser-use), with two tabs open on `/settings`. Screenshots are kept outside the repo in the scratch directory `work/W2.7` and referenced by filename. No product code was changed. Port 4300 and `~/.pharos` were not touched.

## Observation log

1. Started stack with `true`. Vite took 5173 (free). `curl localhost:5173/api/agent` returned the 4392 server's data, so the proxy followed `PHAROS_SERVER_URL`.
2. `/settings` showed Appearance (Light, Dark, System radios, System selected), Answering (switch on, "On: new questions are answered automatically", Agent `true`), and Data and connection (port 4392, MCP `http://localhost:4392/mcp`, version 0.1.0, 0 projects, 0 revisions). All paths were the scratch paths.
3. Theme flash probe: a same-origin iframe loaded `/settings` and was polled with a zero-delay timer from the parent from the moment of navigation. Every sample, including the first at `readyState=interactive` (before React rendered anything into `#root`), already had `class="dark"`. The inline script in `index.html` therefore applies the theme before first paint. Limit: this is a DOM-state probe, not a frame capture, so a sub-frame flash cannot be ruled out in a strict sense. A CDP new-document script probe did not report data in this setup and was dropped.
4. Two-tab test, as in the table. Update arrived within the 1.5 s wait, with no reload (SSE `agent` event).
5. Restarted with `off` on the same scratch database. The Appearance choice (browser localStorage) survived. Off state as in the table. In light theme the same explanation is shown (`08`).
6. Shutdown: all dev processes stopped; `lsof` showed nothing listening on 4392 or 5173.

## Findings

1. No defects found in the three checked behaviors.
2. Minor, same as W2.3 finding 2: in the off state the switch is disabled with no tooltip; the status line carries the explanation. Cosmetic.
3. The "Agent" row shows "None" in the off state, which is clear next to the Off status line.
4. Process note: my shutdown used broad `pkill -f` patterns for tsx and vite, which could also stop an unrelated dev stack on the same machine. Use the PID of the background job next time.
